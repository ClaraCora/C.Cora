# 稳态内存优化与真机验证

本次增加按需内存归因，并在手动释放或内存压力时回收两个闲置大缓冲池。
正常转发的网络栈、队列、并发、功能与 GC 参数保持原值。31 MB 本身不足以
判断泄漏，本次也不承诺降到某个固定内存数值。

## 已实现

- `RuntimeStats()` 增加缓冲池、DNS/Fake-IP、Provider、策略组、GEO 资产和
  Darwin TUN 等待队列信息；原 JSON 字段保持兼容。
- `ForceGC()` 顺序为回收闲置大 buffer，再由 `FreeOSMemory()` 完成 GC 和
  Go 空闲页归还。手动释放与压力事件共用 20 秒冷却，抑制连续回收。
- 开发者诊断显示来源分类、Go GC 元数据以及最近释放前后的物理内存、堆和
  缓冲池对比。摘要保留最近完整对比，详细日志轮转后仍可导出。
- 正常使用不新增后台采样；只有原开发者模式或用户主动查询收集这些指标。

两池合计最多保留 1,048,832 字节，触发时仍在使用的 buffer 不会释放。
其释放量表示移除的池引用；GC 和系统最终归还多少物理页必须实测。

## 指标解释

| 指标 | 用途与限制 |
| --- | --- |
| `physFootprint` | iOS 对 NE 的物理内存记账，判断退出风险的主要参考 |
| `heapAlloc` / `heapInuse` | Go 存活对象与已使用堆页；两者差值可能包含碎片 |
| `heapIdle` / `heapReleased` | Go 空闲页与已归还页；并非物理内存中额外独立类别 |
| pool retained / trimmed bytes | 显式大缓冲池的闲置块，已包含在 Go 堆中 |
| TUN queued packets / bytes | 等待队列中的包数和包长度，非完整 gVisor 内存 |
| DNS / Fake-IP entries | 当前保留条目；持久化 Fake-IP 不扫描数据库，数量留空 |
| Provider nodes / rules | 各 Provider 条目合计，多个 Provider 可能包含重复条目 |
| GEO asset bytes | 磁盘文件大小，不能作为加载后的堆或物理内存大小 |

这些项目相互重叠或单位不同，不能相加作为内存来源百分比。字段缺失表示
未采集或不支持，不当作零；旧 NE 仍可查看原有诊断。

## 本地验证

已通过默认和 `with_low_memory` Go 测试、受影响 Mihomo 包与封装层的 Go vet、
四份补丁的干净应用和原功能补丁 SHA 检查。Darwin/arm64 Go 代码交叉编译
通过，但这不能代替完整 XCFramework、Swift/Xcode、race 与真机验证。
CI 已接入这些 macOS 检查，最终构建结果与真机运行效果仍需在对应环境确认。

## 真机对比步骤

1. macOS 先完成标准/Legacy XCFramework 和完整 Xcode 构建，运行新增 Swift
   分析器测试、Darwin 队列测试及 race 检查。
2. 相同设备、系统和配置分别运行旧版与新版。开发者模式状态保持一致，先
   预热 Provider/GEO，再比较稳定闲置、浏览、下载与测速场景。
3. 高占用时长按总览 NE 内存执行已有手动释放。导出开发者诊断，查看
   最近释放对比；等待超过 20 秒再做第二次对比。冷却期间不会重复 GC。
4. 回归 12 路 IPC、大订阅、长节点名、Provider 更新、配置重载、DNS/Fake-IP、
   解锁脚本及排行榜；验证 5G→4G、弱网恢复、锁屏和 App 划掉后持续转发。
5. 每版至少连续运行 48 小时，记录物理内存峰值/闲置值、Go 堆及已归还页、
   缓冲池保留量、GC CPU/暂停时间、吞吐、延迟与检测成功率。出现 VPN 退出时
   同时保留系统 Jetsam/崩溃记录，避免仅凭最后一个内存数值判因。

正常转发性能与功能无明显回退、释放后内存能够回落、长时间运行无异常断开，
才算完成真机验收。空池或主要是活跃对象时手动释放收益可能很小；不要为了
满足某个数值频繁强制 GC。若重复对比确认回退，按补丁档案整体回退本次
诊断/回收接口，保留此前的功能补丁和用户配置。
