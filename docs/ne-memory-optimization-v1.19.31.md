# Mihomo v1.19.31 与 NE 内存优化验证记录

实施日期：2026-09-30。App 版本：1.0.7。

## 内核和依赖

- Mihomo 升级至 v1.19.31，go.mod、go.sum、补丁名称和准备脚本同步更新；Go 工具链仍为 1.25.4。
- 保留 MRS 有界解压、缓冲池、渐进配置解析、关闭连接队列、保留地址拦截和 DNS 原子更新补丁。
- sing-tun 迁移至 v0.4.24。新版上游默认使用一个接收处理器，项目继续固定一个处理器，并保留接收队列边界和 128 包发送队列；没有进一步缩减这些限制。
- gVisor 更新为 79317d808312，保留纯 ACK 队列限额；sing-shadowsocks2 更新至 v0.2.8，保留长度缓冲和关闭清理补丁。

排行榜、解锁检测并发、gVisor、常规 GC 参数、测速并发和历史采样频率保持原设置。本轮没有精简配置、替换 DNS 索引或增加后台诊断采样。

## 大响应传输

节点目录、连接详情、节点摘要和脚本响应新增 `[]byte` 接口，共享原来的 JSON 编码实现。NE 直接使用 NSData 桥接后的 Data，省去中间的 Go 字符串和 NSString 再编码；跨语言桥接仍会复制数据。

旧字符串接口及 IPC 命令保持兼容。现有历史快照接口继续使用原来的字节传输方式。

## 分块响应缓存

缓存参数为 12 个槽位、8 MiB 总载荷、30 秒有效期，每块 12 KiB。超过 16 KiB 的 IPC 回复继续使用原来的分块描述符。

- 单响应不超过 64 KiB，且所有内存载荷合计不超过 512 KiB 时，优先放内存。
- 更大的响应或内存预算不足时，写入 NE 私有临时目录 `cora-ipc-responses`。
- 文件逐块读取，不把整份文件重新读入内存，也不使用内存映射。
- 最后一块读完、超时、淘汰、文件读取失败和 VPN 会话结束时清理文件；NE 进程下次启动清理遗留文件。
- 写文件不持缓存锁，写完后重新检查会话代次，旧会话任务不能将响应装入新会话缓存。
- 文件和目录采用首次解锁后可访问的保护级别，支持之后锁屏期间读取。首次解锁前仍可能不可用。
- 写入失败时，只有剩余内存预算足够才回退，否则返回明确错误。
- 开发者模式导出分别记录 IPC 内存字节和文件字节；原总载荷字段保留，App 分析兼容旧日志。

512 KiB 只限制留存在缓存中的响应载荷。编码、桥接、正在执行的请求、文件系统缓存与内核转发仍有各自的内存开销，不能将其解释为整个 NE 的内存上限。文件方案会引入短暂磁盘读写，需要真机检查大响应延迟和检测成功率。

## 手动释放空闲内存

连接 VPN 后，长按总览的 NE 内存数值 0.6 秒触发回收。执行期间显示进度，完成后提示回收量或当前内存；VoiceOver 提供同一操作。触摸区域至少 44 点，保持现有胶囊样式。

NE 在生命周期串行队列执行现有 `ForceGC`，每会话设置 20 秒冷却。它会触发一次 Go GC 并归还空闲页，临时压力参数沿用现有实现，之后恢复原值。操作不会关闭连接或清除排行榜，但主动 GC 可能带来短暂运行开销。

App 丢弃断开后返回的旧结果，并阻止之前发出的内存轮询覆盖回收后的数值。用户未开开发者模式时，不开启额外采样；已开启时记录回收前后事件。

仍被连接、规则和缓存使用的内存无法通过此操作释放。回收后数值可能不降，也可能因同时发生的流量或加载而上升；该操作不代替内存泄漏定位。

### 编码分配基准

同一合成节点目录，8 个策略组引用相同节点集合，`with_gvisor,with_low_memory`、GOMAXPROCS=4；每项 3 次 500 ms，取累计分配中位数。字符串路径和字节路径输出完全相同。

| 唯一节点数 | JSON 字节 | 字符串路径 B/op | 字节路径 B/op | 分配减少 |
| --- | ---: | ---: | ---: | ---: |
| 1,000 | 194,969 | 730,684 | 522,595 | 28.5% |
| 5,000 | 970,969 | 3,594,939 | 2,578,854 | 28.3% |

这是 Go 编码累计分配，未包含 Swift 桥接、磁盘缓存和整段 IPC 传输，不代表 NE 物理内存降幅或 iOS 吞吐量提升。

复现：配置好依赖补丁后，在 MobileCore 运行：

```sh
go test -tags with_gvisor,with_low_memory -run '^$' \
  -bench BenchmarkProxyCatalogBridgeResponse -benchmem -benchtime=500ms -count=3
```
