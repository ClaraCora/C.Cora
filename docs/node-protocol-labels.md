# 节点协议标签（2026-09-30）

展开后的节点网格卡片和列表行在左下角显示协议类型，右侧继续显示延迟。分组大卡片不变；引用策略组的条目保留原有分组说明。标签使用系统 caption2 字号和次要文字颜色，大字号或宽度不足时允许分行；VoiceOver 会朗读协议类型。

## 数据与兼容

- 在线 `queryProxies` 响应增加 `nodeTypes` 对象，格式为节点名到 Mihomo adapter 类型字符串的映射。沿用原有策略组成员遍历，覆盖 Provider 节点并按名称去重，不调用节点的完整 JSON 序列化。
- 离线快照复用已有 `nodeTypes`，补齐 Mihomo 六个内置出口的类型。App 将 `Shadowsocks`/`ss`、`Snell`/`snell` 等统一为 `SS`、`SNELL`，只保留一份共享标签映射。
- 缺失、格式错误、未知类型或策略组类型不显示标签，不根据节点名称猜测。旧 NE 响应不含 `nodeTypes` 时正常加载目录。配置替换、会话重置、加载失败和在线直连模式会替换或清空标签；过期响应沿用现有 generation 检查。
- 不增加请求、轮询、网络访问或 NE 常驻类型表。类型表仅在查询期间构建，较大响应沿用现有短期分块缓存及其内存限额。转发路径没有修改。

## 查询分配测量

Windows/amd64、Go 1.25.4、GOMAXPROCS=4，使用项目已有的 Mihomo 补丁依赖和 `with_gvisor,with_low_memory`。每个节点名称包含中文，8 个策略组共享同一批 SS 节点，每项运行 3 次、每次 300 ms，表中取中位数。基线为修改前的查询代码，优化后使用首个组的成员数预分配类型字典。

| 唯一节点数 | 原 JSON 字节 | 新 JSON 字节 | 原分配 B/op | 新分配 B/op | 原耗时 ms | 新耗时 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 16955 | 20369 | 59715 | 76158 | 0.0317 | 0.0540 |
| 1000 | 160955 | 194969 | 511638 | 735566 | 0.2667 | 0.5358 |
| 5000 | 800955 | 970969 | 2604178 | 3601156 | 1.1790 | 2.6594 |

1000 个节点每次查询增加约 33.2 KiB 响应数据、0.21 MiB Go 累计临时分配和 0.27 ms 编码耗时。5000 个节点增加约 166 KiB 响应数据、0.95 MiB Go 累计临时分配；类型信息只随唯一节点数增长，不按分组重复编码。

这些是查询过程的 Go 分配和耗时，不是 NE 物理内存峰值或常驻内存增量，也不包含跨语言桥接、Swift 解析、IPC 分块缓存及 UI 渲染。实际 iPhone 表现仍需真机确认。

复现命令（先按项目脚本准备补丁依赖）：

```sh
go test -tags with_gvisor,with_low_memory -run '^$' -bench '^BenchmarkProxyCatalog$' -benchmem -benchtime 300ms -count 3
```
